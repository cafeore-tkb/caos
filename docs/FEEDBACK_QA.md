# 注文別フィードバックと操作の確認

## 自動テスト

`npm run test:training` で、採点・再生・履歴・操作の回帰テストを実行する。今回追加した確認は次のとおり。

- 未割当へ戻したカードを繰り返しまとめ直して分けても、全カップIDと注文番号が残る。
- 一度分けたカードを待機中にまとめ直して分けても、カードのキーが重複しない。
- 注文到着から抽出開始まで待った場合も、淹れ直し登録後の元カップを破棄できる。
- 抽出が短い、8分を超えた、同じ注文の仕上がりがずれた、アイスの担当選びを見直せる場合に、該当注文と失点が一致する。
- 未到着・担当待ち・順番待ち・抽出中・「終える」の押し忘れを区別する。始まっていない抽出の開始時刻を作らない。
- 項目の失点、条件違反、四捨五入、0点の下限、79点上限を含めて結果の点数と一致する。
- 実際のカップ記録を完了見込みで上書きしない。旧履歴と、振り返り部分だけが壊れた履歴も読み込める。

Workerの結合テストは専用のローカルD1とポート8789で実行し、再生・採点・保存を確認する。本番ランキングには確認用の記録を送らない。

## ブラウザで確認した操作

ゲームで実際に注文を受け、担当への割り当てと抽出終了を操作した。#101は0:30に抽出を始め、9:46に終了した。結果と保存後の履歴は、8分の目標を1:46超えたことによる12.5点の失点を示した。注文番号を#101へ絞ると、その注文の操作時刻と改善案を表示した。

幅767px・高さ1024pxの表示で、時計を0:00から5:00へ進めた。NOWの画面上の横位置は372.6171875pxのままで、盤面全体の横スクロールは0pxだった。番号検索では追従を外し、「現在に戻る」で同じ位置へ戻って追従を再開した。

緊急の元カードと新しいカードを両方残し、新しいカードを未割当へ戻してから選び、3番へ割り当てた。選択前・選択後・割当後のNOWはすべて372.6171875px、追従は有効、盤面全体の横スクロールは0pxだった。

ゴミ箱を押すと元の1杯の確認が開き、確定後は元カードだけが消え、3番の緊急カードが残った。

## 文言の見直し

利用者が指定した [yomiyasu](https://github.com/nanaism/yomiyasu/blob/main/skills/yomiyasu/SKILL.md) の手順で、UIから抽出した文言のlintと差分検査を実行した。配点への「点」の補足、90%の「9割」への言い換え、違反なしの「0回」への言い換え、表示名の「キュー」から「待ち列」への変更、完了予測の「見込み」への言い換えは、元の意味と採点コードに照らした。同じ文末の指摘は説明の文として残し、「—」は値がない表示として残した。検査の実行とハッシュの照合は、文章の意味や読みやすさの合格判定ではない。

```text
yomiyasu-check: executed via=verify run=20261028T164758Z-06c052fe attempt=1 final=sha256:8a1a77e97102 mode=rewrite checks=lint,diff meaning_risk=13 replay=skipped
```

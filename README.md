# CaOS — Cafeore Operating System

コーヒー提供現場で、6人のドリッパー（抽出担当者）へ注文を割り当て、進行状況を一画面で把握するためのタッチ操作向けUIモックです。iPadの横画面を想定し、管制盤を常に表示したまま操作できます。

これまでに決定した画面・操作・業務ルールの詳細は、[画面設計・操作要件](./DESIGN_REQUIREMENTS.md)を参照してください。

## ゲームモード（店舗運営トレーニング）

ヘッダーの「ゲーム」、または `/#training` から開始できます。A・Cのマスターシートを使い、注文到着・時計・抽出が共通の速度（1〜10倍、0.5刻み）で進みます。通常の管制盤はゲーム中に停止し、ゲームだけを開いた場合はPOS APIへ接続しません。

| モード | 営業時間 | 標準速度と所要時間 | 注文件数 | 抽出杯数 | 課題 |
| --- | --- | --- | --- | --- | --- |
| ファスト | 10分 | 2倍・約5分 | 6件 | 10杯 | 基本の割当・完了 |
| ミドル | 20分 | 3倍・約6分40秒 | 12件 | 23杯 | 指名・限定豆・複数商品の並行処理 |
| フル | 30分 | 4倍・約7分30秒 | 44件 | 66杯 | 連続した注文集中・分割・仕上がりの調整 |

80点以上を**店舗運営を任せられる操作レベル**と表示します。各モードではその課題の達成目安とし、総合的な確認にはフルを使います。採点・必須条件・JSON仕様は [トレーニング仕様](./docs/TRAINING.md) を参照してください。

- 添付 `master-2026-10-19_03-34.json` の12商品・略称・商品種別・色設定を同梱。ミルクと物販は抽出せず、限定豆は上級生（1・6番）へ割り当てます。
- 指名・上級生限定・コメント付きの注文を混ぜます。ファストは1/1/1件、ミドルは2/1/2件、フルは3/2/3件（それぞれ指名/限定/コメント、重複あり）。コメントは吹き出し・カードの操作メニュー・未提供一覧から確認できます。
- 架空の注文をモード別の [JSON](./public/training) として同梱。モード選択画面で内容を確認・ダウンロード・差し替えできます。実注文データは使いません。
- 途中終了と時間切れの両方で、全シナリオを分母として採点。採点内訳・改善点・操作ログを表示し、結果JSONを保存できます。最新100回の得点はこのブラウザに保存します。
- 緊急淹れ直しはミドルで50%×1回、フルで独立した50%×2回。対象の抽出が75%進んだ時点で通知し、杯数・担当者・元抽出の中断／継続を選んで対応します。
- 開始時は空の盤面です。未割当を担当者へ配置すると、空の列では抽出を開始します。カードの操作メニューから未着手への戻し・開始・完了を操作できます。同じ商品の1杯同士は、指名条件が矛盾しなければ2杯へ統合できます。

```bash
npm run training:generate # マスターから架空注文のテンプレートJSONを再生成
npm run test:training     # 採点・進行・データ検証のテスト
```

A・CのUIは `cafeore-pos/main` の `173c9f18b71a4435fd967916378ed4df06efdbc4`（2026-10-25取得）と [現行マスターシート](https://cafeore-pos.cafeorepos.workers.dev/master-sheet) を参照しています。A/C・カード・操作メニュー・フォルダタブ・未提供一覧・タッチドラッグを含む表示コンポーネントを直接移植し、共通の盤面へ接続しました。通常画面・ゲーム中ともA/Cを自由に切り替えられ、注文・抽出・得点を維持します。移植元とアダプターの詳細は [UPSTREAM.md](./src/current-caos/UPSTREAM.md) に記載しています。

## 画面

- **A**: NOW線を基準に、6人のレーンと時間軸で進行・待機カードを確認する管制盤。下の未割当は注文番号の列ごとに並び、同じ注文のカードを縦に重ねます。
- **C**: 6人の担当者を行にして、現在の抽出と待機列を横並びで確認する画面。未割当は右側の注文キューに表示します。
- 通常画面とゲーム中のヘッダーから、A/Cをいつでも切り替えられます。表示だけが切り替わり、注文・抽出・採点の状態を維持します。
- 注文番号・杯数・商品名を共通のカードで表示し、指名は点線枠と番号、商品の種別はマスターの色設定で識別します。
- 未割当は全件を保持し、Aでは見出し右の横スクロールバー、Cでは縦スクロールバーから確認できます。
- 補助情報は右側パネルに表示し、管制盤全体を隠しません。

## 主な挙動

- 初期状態は全ドリッパーが空で、cafeore-pos で受けた注文が届いた順に未割当へ追加されます。
- 未割当は注文番号ごとに表示します。列の待機順は、カードの前後へのドラッグで変更できます。
- 指名注文は指定されたドリッパーにのみ割り当てられます。
- 1回の抽出は最大2杯です。3杯以上の注文は2杯以下のカードへ自動分割します。
- 同じメニューの1杯カード同士だけ、利用者の判断で2杯の同時抽出へ統合できます。
- 抽出は1杯5分・2杯6分。時間だけでは完了せず、カードの「終える」で完了し、待機の先頭を開始します。
- 待機・抽出中カードの移動や未割当への戻しに対応します。抽出中カードを移すと抽出時刻をリセットします。
- 商品名・略称と、マスターの商品／商品種別／指名の色設定を使います。
- 同じ注文が複数カードに分かれていても、注文番号のハイライトと未提供一覧で追跡できます。
- 抽出中・完了済みカードから緊急の入れ直しを開始でき、中断／継続、杯数、担当者、差し込み位置を利用者が選べます。
- アイスミルクは売上分析には残しつつ、ドリップ管制の未割当・タイムラインから除外します。

## cafeore-pos 連携

- 注文は常に cafeore-pos と同じDBから取り込みます（ゲームモードは独立した架空注文を使用）。ヘッダーのDBアイコンの点が接続状態で、緑は接続済み、黄は接続中・再接続中です。
- 実データテスト中はDBからの取り込みを止め、テストの注文だけで動かします。終了後の実績表示中も止めたままで、リセットするとDBの注文に戻ります（未準備の注文を取り込み直します）。
- 注文は cafeore-pos のAPI（`/api/ws/orders`）からWebSocketで受け取ります。当日の注文のうち、準備完了・提供済みでないものを未割当に追加し、POS側で準備完了・提供済み・削除になった注文は、未割当に残っている分だけ外します。
- 読み取り専用です。ドリッパーへの割当や抽出完了 はCaOSの画面内だけの状態で、DBには書き込みません。
- 同梱マスターにある商品はその設定で判定します。それ以外の既存商品は名称・商品種別から分類します。アイスミルクとグッズは除外します。
- POSの指名は、`1`〜`6` の番号か現在のドリッパー名に一致したときだけその担当者に固定し、一致しないときはカードに「（指名:名前）」と表示します。
- 開発サーバー（`npm run dev`）では Vite の中継（`/cafeore-pos-api`）を通して本番APIにつなぎます。ローカルのAPIを使うときは `VITE_CAFEORE_API_BASE_URL=http://localhost:8080` を指定します。
- 公開版はブラウザから本番APIへ直接つなぐため、APIの `FRONTEND_ORIGINS`（infraリポジトリの `gcp/cloud_run.tf`）に `https://cafeore-tkb.github.io` が入っている必要があります。入っていないとWebSocketの接続が403で拒否され、DBアイコンの点が黄色（再接続中）のままになります。

## 実データ・テストプレイ

- ヘッダーの「テスト」から、2025年の実注文を使ったテストプレイを開始できます。
- 開始前に時間帯と30分／1時間を選択します。ヘッダーの `1x / 2x / 5x / 10x` に合わせて、時計・タイムライン・注文到着・抽出時間が実時間基準で一緒に進みます。
- 「終了・実績」を押すと、売上、商品構成、ピーク、提供時間、担当量、分割注文の仕上がりΔを表示します。
- 指定された `2025/data/day1.json` は空ファイルだったため、同じリポジトリにあるダミー除去済み `2025/data/day12.json` を軽量化して同梱しています。
- 実績データはビルド時に遅延読込用JavaScriptへ内包し、公開サイトに生JSONのURLを作りません。
- データ出典: [cafeore-tkb/sohosai-analysis](https://github.com/cafeore-tkb/sohosai-analysis/tree/main/2025/data)

## 公開構成

- ソースと実績データはPrivateの `cafeore-tkb/CaOS` で管理します。
- Private側のActionsは、PRで検証だけを実行し、`main` 更新時は検証した成果物を自動で公開します。
- 採点APIを同じ版へ更新してから、ビルド成果物だけをPublicの `cafeore-tkb/digital-master-sheet-pages` の `site/` へ送ります。公開側のPagesワークフローが更新し、配信された版まで確認します。
- `npm run publish:pages` は手動で再公開するときに使えます。通常は実行不要です。
- `main` の成果物を `site/` 直下に配置します。
- 実注文の生JSONは公開せず、実績データは遅延読込JavaScriptへ内包します。架空のトレーニング注文JSONはダウンロード用に公開します。

## タッチ操作

- 未割当カードをタップすると、カードを隠さず上下に1〜6の割当ボタンが開きます。
- 指を離さず割当先へなぞる操作と、レーンへのドラッグ操作に対応しています。
- 枠外をタップすると選択状態を解除します。
- タイムライン上の未開始カードも、同じ操作感で割当先を変更できます。

Node.js 22を推奨します。

```bash
npm install
npm run dev
```

開発サーバーは `http://localhost:3000` で起動します。


### 操作チュートリアルと振り返り

「訓練」は全10レッスンのチュートリアルから始まります。実際の盤面で操作を確認してから、ファスト・ミドル・フルのゲームへ進めます。経験者は直接ゲームを選べます。進捗と採点結果はこのブラウザに保存され、履歴から日時・採点内訳・改善点・操作記録を確認できます（最新100回、旧版の点数も継承）。サイトデータを削除すると記録も削除されます。

マスターシートは2026-10-25取得の `cafeore-pos/main@173c9f18` に更新。A/Cのカード表示、操作トレー、注文強調、Cの全注文一覧・コメントチャット、スタンプ、淹れ直し元の破棄確認を訓練に採用しています。

チュートリアルの説明はフローティング表示です。操作する場所へ赤い矢印と強調枠が移動し、盤面の配置を変えずに案内します。ガイドは小さくたため、動きを減らすOS設定にも対応します。

## 共有ランキングと2つのスコア

標準ゲームの開始前にプレイヤー名を入力すると、終了後にCloudflare Worker＋D1で操作を再生・採点し、自動でランキングへ掲載します。ランキングは誰でも見られます。マスター評価（100点）と営業スコア（売上＋指名・限定・2杯統合ボーナス）は切り替え可能。注文内容と到着時刻は毎回抽選し、同じモードの杯数・商品構成・売上上限をそろえます。ゲーム履歴は従来どおり端末にも保存します。設定・運用は [ランキングAPI](./worker/README.md) を参照してください。

最後のチュートリアルはシフト交代です。10:00〜11:00の例で、10分前の予告、5分前の強調、予定の人への交代、6人のワンタップ交代、誤タップ注意、二度目のタップから学年で予定外の人を選ぶ操作、名前入力、担当者交換、空きと復帰を練習します。

マスター評価にA+・A・B・C・Dの評定を表示します。A+は95点以上、かつ同じモードの受講者の上位10％未満（同点者全員を含む）。Aは80点以上でA+以外、Bは70点以上、Cは60点以上、Dは60点未満で不合格です。相対評価は現行ルールの挑戦者1人につき自己ベスト1件から算出します。端末のみではAまでとし、表示名で掲載した後にA+を共有ランキングで確定します。履歴は保存時の評定を表示します。店舗運営の目安は80点以上のままです。

ランキングへの掲載は「プレイヤー名 → ゲーム → 結果を自動掲載」。前回の名前は開始欄に補完します。通信失敗時は名前と操作記録を保って再送でき、結果は端末にも保存されます。同じ表示名は別の端末からでも1人分にまとめ、別の名前は独立した記録になります。ユーザー名・パスワード・事前登録は不要です。

練習ゲームの速度は1〜10倍を0.5刻みのスライダーで変更できます。フルは繁忙時30分40件60杯の110%（44件66杯）。コーヒー名は同じ数量・限定条件の枠で毎回入れ替え、総杯数と商品別売上上限を保ちます。条件変更前の結果は端末に残し、共有ランキングは現行ルールの記録で比較します。

フルは開始時点で8件12杯の注文が到着済みです。全注文の割当と緊急対応の手配を終えると、タイムライン上の開始時刻＋抽出時間で完了予測を算出し、自動採点します。営業30分を延長せず、実際に終えた杯と未完了分の見込みを分けて記録します。完了予測の速さは33分（66杯を6台で2杯ずつ抽出する最短目安）で25点、その後15分の遅れで0点へ比例して減点します。

結果と履歴では、「どの注文で何点下がったか」「次はどう操作するとよいか」を確認できます。注文番号で絞ると、到着から抽出終了までの実際の時刻が並びます。79点の上限がかかった理由も、項目ごとの失点と分けて表示します。詳しくは[注文ごとの振り返り](./docs/TRAINING.md#注文ごとの振り返りと操作の修正2026-10-29)と[確認した操作](./docs/FEEDBACK_QA.md)を参照してください。

緊急カードを担当へ割り当てるときは、現在の線の位置と追従を保ちます。カードを選ぶだけでは同じ注文番号の元カードへ画面を動かしません。番号で探したときはその注文を表示し、「現在に戻る」で今の時刻へ戻れます。
